# WebDAV 配置与双端使用

## 选择存储

第一阶段不绑定供应商。建议先使用已经拥有、可稳定通过 HTTPS 访问的 WebDAV 服务；自建时使用支持原子 `If-None-Match: *` 的 WebDAV 服务器和有效 TLS 证书。暂不为任何商业网盘的兼容性背书；请以应用连接测试和双机验收为准。普通网盘目录、只读分享链接、同步盘客户端本地文件夹都不能代替 WebDAV URL。

建议创建独立空目录、独立账号或应用专用密码，将权限限制在该目录；不要把主账号密码填入样例代码或 GitHub Secrets（本项目的 CI 完全不需要 WebDAV 密钥）。凭据只在应用设置页输入并存放于操作系统安全存储。

服务须支持 HTTPS、MKCOL、PROPFIND Depth:1、GET、PUT、DELETE。重复条件 PUT 必须返回 412，不能覆盖原内容。填写最终地址；应用拒绝所有 HTTP 重定向，也不会忽略证书错误。

## 首台设备

1. 先在 WebDAV 服务中准备好根目录，例如 `https://dav.example.invalid/personal-ledger/`（此地址只是示例，不能连接）。
2. 打开 MyLedger → 同步设置，填根目录、用户名和应用专用密码。
3. 保留自动生成的账本 ID，点击“验证并保存”。测试会在应用目录中创建并清理独立探测文件。
4. 返回首页，等待“同步完成”；首页显示待上传操作数量。新增分类后再新增账目。

## 第二台设备

1. 安装并打开应用。在录入任何分类或账目前进入同步设置。
2. 从首台设备复制账本 ID，填入第二台空设备的账本 ID。
3. 填入同一 WebDAV 根目录及凭据，点击“验证并保存”。返回首页后自动拉取。
4. 两台设备分别离线新增测试账目，恢复网络并同步，确认均可看到对方记录。

已有记录的设备不能直接改账本 ID，以免把两套账本混在一起。第一阶段没有账本合并或清库按钮；若误在第二台设备录入了内容，请保留现有数据，先停止同步并规划导出迁移，不要卸载后覆盖唯一副本。

## 冲突与失败

两台设备离线修改同一笔账目时，首页会出现冲突入口。展开后选择保留的完整版本；原始版本保留在操作日志。冲突账目不计入月度合计，界面会标明排除数量。分类冲突也必须手动处理。

网络失败后可继续本地记账。每次网络请求的暂时失败会有限重试；下一轮自动或手动同步继续处理待上传记录。不要通过复制 SQLite 文件、修改 JSON 日志、清空 WebDAV 目录来“解决冲突”。

连接测试会验证读、写、列目录、原子创建与删除探测文件。若提示条件写入不支持，需要修复服务器或更换服务。若日志缺少父版本，可能是暂时列表不同步；稍后重试。若持续报错，请保留所有日志和本地数据进行诊断。

## 数据与恢复

服务端日志是明文 JSON，HTTPS 并不等于端到端加密。不要把根目录公开分享。Android 系统自动备份已禁用，避免安全凭据恢复与密钥不一致。日常应维护服务端版本或独立备份。第一阶段没有应用内备份恢复向导，不要把同步当作完整备份方案。

如果远端目录误删，而某台设备仍保留完整日志，重新连接时应用会重建远端历史。若远端被篡改，应先停止所有设备同步并保留现场；校验和不是抵御恶意服务端的签名。卸载可能删除本地账目和凭据，卸载前务必确认备份。
